## 新发现

### R10 · P2：外键动作已声明但运行期未启用，删除不做级联清理

- 关联任务：03、12、15。
- 位置：`lib/database/database.dart:60-91`（无 `beforeOpen`、无 `PRAGMA foreign_keys`）、
  `lib/features/nodes/service.dart:147-152`、`lib/providers/actions/profiles.dart:20-34`、
  `lib/providers/database.dart:66-74`。
- 现象：`lib/database/nodes.dart`、`lib/database/chains.dart` 为 Profile / 节点外键声明了
  `KeyAction.cascade` 与 `KeyAction.setNull`，但 SQLite 的 `foreign_keys` 默认关闭；
  drift 2.34.3 不会自动打开（`migration.dart:313` 只在 `alterTable` 结束时恢复原有状态），
  仓库内也没有任何位置执行该 pragma。
- 复现：本轮用一次性探针测试在内存库上实测（跑完即删除，未留在仓库）。
  播种一个 Profile、一个 `source_profile_id = 1` 的节点、节点绑定、链、hop、链绑定和资产后：

  | 操作 | 实测结果 |
  | --- | --- |
  | `PRAGMA foreign_keys` | `0`（关闭） |
  | 删除 `proxy_nodes` 行 | `profile_proxy_nodes` 残留 1 行；`proxy_chain_hops` 残留 1 行且 `node_id` 仍为 100；`proxy_node_assets` 残留 1 行 |
  | 删除 `profiles` 行 | `profile_proxy_nodes` 残留 1 行；`profile_proxy_chains` 残留 1 行；节点 `source_profile_id` 仍为 1，未置空 |

- 后果：
  - 删除节点：`NodeLibraryService.delete` 只删 `proxy_nodes` 行与资产目录，
    `profile_proxy_nodes`、`proxy_chain_hops.node_id`、`proxy_node_assets` 留下悬挂行。
  - 删除 Profile：`ProfilesNotifier.del` 只删 `profiles` 行并清理 Profile 文件，
    `profile_proxy_nodes` / `profile_proxy_chains` 残留，来源节点的 `source_profile_id` 不会置空。
- 与验收标准的关系：Task 03 的「Profile 删除时来源 Profile 置空，显式绑定随 Profile 级联清理」
  与「节点删除时节点绑定、hop 和资产记录按外键策略清理」当前不成立，
  且 `test/database/` 没有任何删除或级联用例覆盖该行为。
- 影响判断：表现为残留行与失效引用；链路侧在组装时会以 `invalid-hop` 反馈，不构成数据损坏，
  但删除后的节点库与绑定状态与文档口径不一致。这一项不是「未验收」，是已实测不成立。
- 建议方向：在 `MigrationStrategy.beforeOpen` 打开 `PRAGMA foreign_keys = ON`
  （需同时确认既有迁移与 `restore(isOverride: true)` 的批量替换路径在开启后仍成立），
  或在 service 层显式清理关联行；两种方案都要补 `test/database/` 的删除用例。
