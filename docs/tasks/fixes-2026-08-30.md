## 逐项修复

### R1 · 备份恢复失败时统一保留旧文件、数据库与设置

- `lib/common/task.dart`：`_restoreTask` 不再在校验前把 Profile/脚本写入正式 home；
  资产校验抽为 `verifyRestoredNodeAssets`，在返回迁移数据前完成路径与 SHA-256 检查。
  新增 `applyRestoredProfileFiles` 与 `RestoredFileTransaction`：覆盖前备份原文件，
  `rollback()` 恢复旧内容并删除新建文件，`commit()` 才丢弃备份。
- `lib/database/database.dart`：新增 `snapshot()` 与 `restoreSnapshot()`，用现有 `restore(isOverride: true)`
  路径回滚到恢复前的行集合。
- `lib/providers/actions/backup.dart`：`restore` 先做配置反序列化校验，再取数据库快照与当前设置，
  然后按 文件 → 数据库 → 节点资产 → 设置 顺序应用；任一步失败即回滚文件、数据库和设置后抛出。
- 测试：`test/common/restore_transaction_test.dart`（坏哈希、缺失资产、越界相对路径、
  文件回滚/提交、数据库快照回滚）。
- 剩余：真实备份 ZIP 的端到端恢复、Task 15 约定的备份 manifest 契约。

### R2 · SOCKS4/4a 导出往返保持版本

- `lib/features/nodes/codec.dart`：新增 `_socksScheme`，导出按 `version`（4 / 4a）选择 scheme，
  同时兼容历史上把版本写进 `type` 的配置。
- 测试：`test/nodes/node_codec_test.dart` 增加导入 → 导出 → 再导入的版本保持断言，并确认 socks5 不受影响。

### R3 · 链路与生成策略组接入导出

- `lib/features/nodes/export.dart`：`exportConfigs` 增加 `groups` 参数，YAML/JSON/ZIP 载荷输出
  `proxy-groups`，ZIP manifest 增加 `groups` 清单。
- `lib/features/chains/chains.dart`、`runtime.dart`：`ChainPreview` 暴露 `generatedProxies`、
  `generatedGroups` 与 `generatedNodeIds`；`ProfileEffectiveConfigService` 增加
  `materializeAssets: false`，导出时使用可移植的相对资产路径。
- `lib/views/profiles/chains.dart`：链库菜单新增导出 YAML / JSON / ZIP，ZIP 内含每个 hop 节点的资产。
- 测试：`node_codec_test.dart` 的生成链导出用例、`profile_effective_config_test.dart` 的预览产物用例。
- 剩余：导出件在其他客户端再导入的语义验收。

### R4 · 链路编辑保存前诊断与确认

- `lib/features/chains/runtime.dart`：新增 `previewChain`，通过 `chainHopOverrides` 与 `previewChainIds`
  复用整条组装管线编译未保存的 hop，不写库、不影响已绑定链。
- `lib/views/profiles/chains.dart`：编辑器显示路径数量与诊断（error 用错误色，warning 用次要色），
  hop 增删改和拖拽后重算；保存时若存在诊断，先弹确认再返回。
- 本地化新增 `chainPathCount`、`chainDiagnostics`、`chainWarningConfirm`（en/zh_CN/ja/ru）。
- 测试：`profile_effective_config_test.dart` 的 chain preview 组（路径数、空链、不可解析 hop、
  生成产物、预览不落库）。
- 剩余：设备上的交互验收。

### R5 · 普通 Rule Profile 的链路显式选用入口

- 模型与存储：`ProxyChainBinding.entryGroups`（`List<String>`）、`profile_proxy_chains.entry_groups` 列，
  数据库 schema 升至 v4，迁移只对 `from >= 3` 追加列。
- `lib/features/chains/service.dart`：新增 `setEntryGroups`。
- `lib/features/chains/runtime.dart`：`_attachChainEntry` 把生成的链 selector **追加**到所选 Profile 策略组，
  组首成员不变，因此原 Profile 选择保留；用户在代理页显式选用该 selector 后流量才走链。
  入口组不存在时给 `missing-chain-entry-group` 警告而不阻断应用。
- `lib/views/profiles/chains.dart`：链库菜单新增“链路入口组”多选，列表副标题显示已选入口组。
- 测试：未设置入口组时规则入口不变、设置后 selector 进入组且原成员仍在首位、禁用绑定后入口移除、
  入口组缺失时告警；另加 schema v3 → v4 升级用例。
- 边界：仍不隐式改写原规则，Global 模式与手工链规则不在此结论内。

### R6 · 仅绑定链时链内手动节点可见

- `lib/features/chains/runtime.dart`：新增 `_chainLibraryNodeIds`，把已启用链绑定的 hop 节点，
  以及 hop 指向的数据库策略组内的手动节点纳入 `visibleNodeIds`；其他 Profile 的来源节点仍被隔离。
- 组装改为一次性预载链绑定、hops、策略组与成员，供可见性计算与后续编译共用。
- 测试：只绑定链、不单独绑定节点时无 `invalid-hop` / `empty-chain`，且生成代理包含该节点。

### R7 · 同名来源节点保持不同端点

- `lib/features/nodes/node.dart`：新增 `SourceNodeKeyAllocator`，统一 `kind:provider:identity[#occurrence]`
  的来源键生成。
- `lib/features/nodes/service.dart` 改用该分配器；`lib/features/chains/runtime.dart` 组装时按
  来源键 + 出现次数认领节点，认领失败再按名称回退，且同名只由首个出现占用名称映射。
- 测试：同一 Profile 两个同名来源节点分别保留 `HOST_A` / `HOST_B`，运行名称各自唯一。

### R8 · Core 应用失败时保留上一份有效配置

- `lib/common/task.dart`：新增 `replaceFileAtomically` 与 `FileReplacement`，替换前保留备份，
  `rollback()` 恢复旧文件或删除新建文件。
- `lib/providers/actions/setup.dart`：`setupConfig` 失败时回滚配置文件，并尽力重载上一份有效配置，
  再抛出原错误；成功后才 `commit()` 并更新 digest。
- `core/hub.go`：`handleValidateConfig` 不再吞掉读文件错误，并在 `UnmarshalRawConfig` 之后
  逐个 `adapter.ParseProxy` 校验 proxies、检查代理与策略组重名（含保留名）。
  未接入完整 `ParseRawConfig`，以免校验触发规则集与 geo 下载副作用。
- 测试：`test/common/restore_transaction_test.dart` 的原子替换用例、`core/hub_validate_test.go` 六项。
- 剩余：真实 Core 的失败注入与快速连续应用/重启场景。

### R9 · Windows 热启动链接转发

- `windows/runner/main.cpp`：按 `app_links 7.2.1` 的示例接入 `SendAppLinkToInstance()`，
  已有实例时转发链接并聚焦窗口后退出，Dart 侧单实例锁不再吞掉链接。
- 剩余：Windows 实机验收（应用关闭 / 已运行两种场景、窗口聚焦、链接去重）。
